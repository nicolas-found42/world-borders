# Domain docs

This repo uses a single-context layout: `GLOSSARY.md` at the root and
architecture decisions in `docs/adr/`.

Before exploring a domain area, read the glossary and relevant ADRs when
they exist. Use glossary terms in issues, tests, and proposals. If a needed
term is missing, record the gap for domain modeling. Surface any conflict
with an existing ADR explicitly.

The glossary and ADRs are created as terms and decisions are settled;
their absence does not block other work.
